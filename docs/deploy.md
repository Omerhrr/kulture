# Deploying Kaduna Kulture to a VPS

Live address: **https://kulture.rogan.live**

The whole sim runs as four Docker containers on one server:

| Container  | What it is                                   | Reachable from        |
|------------|----------------------------------------------|-----------------------|
| `caddy`    | HTTPS (auto Let's Encrypt), routes traffic   | the internet, 80/443  |
| `frontend` | Nuxt game client (production build)          | caddy only            |
| `backend`  | FastAPI + WebSocket, runs migrations at boot | caddy only            |
| `db`       | PostgreSQL 16, data in the `pgdata` volume   | backend only          |

`/api/*` and `/ws/*` go to the backend and everything else to the frontend, all
on one origin, so the client needs no extra configuration.

## 1. Server

- Ubuntu 22.04/24.04 or Debian 12, **2 vCPU / 4 GB RAM** recommended (2 GB works:
  setup adds 4 GB of swap for the frontend build), 25 GB disk.
- Root SSH access.

## 2. DNS (do this first, certificates need it)

At the DNS provider for `rogan.live`, add:

| Type | Name      | Value          |
|------|-----------|----------------|
| A    | `kulture` | your VPS IPv4  |
| AAAA | `kulture` | your VPS IPv6 (only if it has one) |

If the domain is on Cloudflare, set the record to **DNS only** (grey cloud)
for the first deploy so Caddy can get its certificate. You can turn the proxy
on afterwards with SSL mode "Full (strict)".

Check it with `nslookup kulture.rogan.live`: it must return the VPS IP.

## 3. First deploy (one command)

The VPS pulls the code from git, so push this repo to GitHub (or similar)
first. For a private repo, add a deploy key on the server.

```bash
ssh root@<vps-ip>
apt-get update && apt-get install -y git
git clone <your repo url> /opt/kulture
bash /opt/kulture/scripts/vps/setup.sh <your repo url>
```

`setup.sh` installs Docker, enables a firewall (SSH, 80, 443 only), adds swap,
writes `/opt/kulture/.env` with fresh random secrets, schedules a nightly
database backup and starts the stack. The first build takes 5 to 10 minutes.
When it prints `live: https://kulture.rogan.live`, the sim is up.

## 4. Shipping changes

Every change after this goes the same way: commit and push from your PC, then

```bash
ssh root@<vps-ip> /opt/kulture/scripts/vps/update.sh
```

It pulls, rebuilds, restarts and waits for the backend to report ready.
Database migrations run automatically at startup, and player data is never
dropped.

## 5. Settings (`/opt/kulture/.env`)

| Key | Meaning |
|-----|---------|
| `KK_DOMAIN` | `kulture.rogan.live` |
| `KK_ENV` | `production`: turns off the dev "simulate wallet payment" button, and refuses to boot on weak secrets or SQLite |
| `POSTGRES_PASSWORD`, `KK_JWT_SECRET`, `KK_ADMIN_TOKEN` | generated by setup. **Changing `KK_JWT_SECRET` logs everyone out.** |
| `KK_LLM_ENABLED`, `KK_LLM_API_KEY` | set `true` plus a DeepSeek key for the AI NPCs and Ask guide; otherwise built-in answers |
| `KK_LIGHTNING_PROVIDER` | `mock` until a real node is connected (see `lightning-integration.md`) |

After editing: `cd /opt/kulture && docker compose up -d`.

## 6. Day-to-day

```bash
cd /opt/kulture
docker compose ps                    # status
docker compose logs -f backend       # live backend log
docker compose restart backend       # restart one service
scripts/vps/backup.sh                # backup now (nightly runs at 03:15)
ls /opt/kulture-backups              # last 14 days of backups
```

Restore a backup:

```bash
gunzip -c /opt/kulture-backups/<file>.sql.gz | docker compose exec -T db psql -U kk -d kaduna
```

Copy backups off the server now and then, for example with
`scp root@<vps-ip>:/opt/kulture-backups/* .`

## Notes

- The backend runs a **single process** on purpose: live multiplayer state
  (presence, shared rides, races) is held in memory. Scale up the server, not
  the worker count.
- Your local `kaduna.db` (SQLite) is not copied. The server starts with a
  freshly seeded city and empty player list.
- The seeded `demo_player` / `kaduna-demo-2026` account is shared and public,
  as shown on the landing page.
